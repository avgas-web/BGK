## 🎯 Внесённые изменения

### Добавлена система ограничения манипуляций

**Правила:**
1. **Каждый тип манипуляции** может произойти **не более 3 раз** за тест
2. **Общее количество манипуляций** не должно превышать **15** (включая повторяющиеся)

---

## 🔧 Техническая реализация

### 1. Система отслеживания лимитов

Добавлены новые состояния:
```typescript
const [manipulationCounts, setManipulationCounts] = useState<Record<string, number>>({});
const MAX_PER_TYPE = 3; // Максимум 3 раза для каждого типа
const MAX_TOTAL = 15; // Максимум 15 манипуляций всего
```

### 2. Функция проверки лимитов

```typescript
const canApplyManipulation = (type: string): boolean => {
  const currentCount = manipulationCounts[type] || 0;
  const totalCount = Object.values(manipulationCounts).reduce((sum, count) => sum + count, 0);
  
  // Проверяем лимиты
  if (currentCount >= MAX_PER_TYPE) return false;
  if (totalCount >= MAX_TOTAL) return false;
  
  return true;
};
```

### 3. Функция увеличения счётчика

```typescript
const incrementManipulationCount = (type: string) => {
  setManipulationCounts(prev => ({
    ...prev,
    [type]: (prev[type] || 0) + 1
  }));
};
```

### 4. Обновлённая функция trackManipulation

```typescript
const trackManipulation = (type: string, name: string, description: string, wikiLink: string) => {
  // Проверяем лимиты перед добавлением манипуляции
  if (!canApplyManipulation(type)) {
    return false; // Манипуляция не добавлена из-за лимитов
  }
  
  // Увеличиваем счётчик для этого типа
  incrementManipulationCount(type);
  
  // Добавляем манипуляцию в список
  setManipulations(prev => {
    const existing = prev.find(m => m.type === type);
    if (existing) {
      return prev.map(m => m.type === type ? { ...m, count: m.count + 1 } : m);
    }
    return [...prev, { type, name, description, count: 1, wikiLink }];
  });
  
  return true; // Манипуляция успешно добавлена
};
```

## 📊 Отслеживаемые манипуляции

### Типы манипуляций:

1. **answer_confirmation** - Подтверждение ответа
   - Максимум: 3 раза
   - Вероятность: 19% при каждом ответе

2. **question_rewrite** - Переписывание вопроса
   - Максимум: 3 раза
   - Вероятность: 70% при каждом ответе

3. **answer_change** - Изменение ответа
   - Максимум: 3 раза
   - Связано с переписыванием вопроса

4. **mockery** - Насмешка над пользователем
   - Максимум: 3 раза
   - Вероятность: 30% при каждом ответе

5. **bsod_screen** - Скример BSOD
   - Максимум: 3 раза (фактически 1 раз из-за bsodShown)
   - Вероятность: 5% при каждом ответе

6. **bios_screen** - Скример BIOS
   - Максимум: 3 раза (фактически 1 раз из-за biosShown)
   - Вероятность: 5% при каждом ответе

7. **dishonesty_accusation** - Обвинение в нечестности
   - Максимум: 3 раза
   - Появляется при возврате на предыдущий вопрос

8. **memory_manipulation** - Манипуляция памятью
   - Максимум: 3 раза
   - Вероятность: 50% при каждом ответе

9. **test_crash** - Краш теста
   - Максимум: 3 раза (фактически 1 раз)
   - Вероятность: 0.5% при переходе к следующему вопросу

## 🎮 Как это работает

### Пример сценария:

1. **Вопрос 1:** Пользователь отвечает
   - Появляется насмешка (mockery: 1/3)
   - Вопрос переписывается (question_rewrite: 1/3)
   - Ответ изменяется (answer_change: 1/3)
   - **Всего: 3 манипуляции**

2. **Вопрос 2:** Пользователь отвечает
   - Появляется насмешка (mockery: 2/3)
   - Появляется BSOD (bsod_screen: 1/3)
   - **Всего: 5 манипуляций**

3. **Вопрос 3:** Пользователь отвечает
   - Появляется насмешка (mockery: 3/3) - **достигнут лимит для mockery**
   - Вопрос переписывается (question_rewrite: 2/3)
   - **Всего: 7 манипуляций**

4. **Вопрос 4:** Пользователь отвечает
   - Насмешка не появляется (достигнут лимит 3/3)
   - Вопрос переписывается (question_rewrite: 3/3) - **достигнут лимит для question_rewrite**
   - Появляется BIOS (bios_screen: 1/3)
   - **Всего: 9 манипуляций**

5. **Вопрос 5-15:** Продолжаются манипуляции
   - Проверяются лимиты для каждого типа
   - Проверяется общий лимит (15 манипуляций)
   - Если достигнут общий лимит, манипуляции не применяются

## 📈 Преимущества системы лимитов

### 1. Контролируемая интенсивность
- Пользователь не перегружается манипуляциями
- Каждый тип манипуляции появляется ограниченное количество раз
- Общий лимит предотвращает чрезмерное воздействие

### 2. Предсказуемость
- Пользователь может пройти тест без чрезмерного стресса
- Манипуляции распределены равномерно по тесту
- Нет ситуации, когда все манипуляции происходят в начале

### 3. Образовательная ценность
- Пользователь видит ограниченное количество примеров каждой манипуляции
- В TestDebrief отображается полная статистика
- Пользователь может понять, какие манипуляции были применены

### 4. Безопасность
- Ограничение общего количества манипуляций (15)
- Ограничение каждого типа (3)
- Возможность отключить все эффекты через стоп-слово
